Failure modes found and fixed

01gemini-2.5 · web-grounded discovery
Broke

The discovery model invented LinkedIn profile URLs — real-looking links with plausible hex suffixes that returned 404. Nothing in the response signalled they were fabricated. I found it by clicking through them.

Built

An integrity gate ahead of the user: URL shape validation, handle-to-entity name cross-checking against a stop-word list, hard stripping of anything unverifiable, and an automatic halt on any search showing sustained fabrication.

Result

430 fabrication events caught and logged over 11 days (2026-06-29 → 07-09), every one blocked before reaching output. Heaviest single case: one invented French eyewear brand returned 196 times and blocked every time. Fabricating searches were halted and re-scoped instead of silently poisoning the dataset.

Learned

A grounded model fabricates identifiers with exactly the same confidence it reports real ones. Never pass an unverified identifier through.

02multi-provider inference
Broke

Empty responses with no usable explanation — no text, no error, just nothing, and a generic failure surfaced to the user that hid the diagnosis.

Built

A four-stage recovery ladder: escalate model, retry with increased grounding, disable search grounding in safe mode, then surface the structured reason (blockReason, finishReason, candidate count).

Result

2,084 key-exhaustion and rotation events absorbed over 9 days without operator intervention, against 57 errors that reached the application layer — a 36:1 ratio of failures handled to failures surfaced.

Learned

A generic error is a decision to discard the only evidence you have. Failures should arrive already diagnosed.

03spreadsheet persistence layer
Broke

A schema change rewrote sheet headers in place, but existing data rows never migrated underneath them. Columns silently pointed at the wrong values.

Built

An append-only rule for every schema change, plus a normaliser reconciling 13 distinct column layouts across ~130 files into one canonical schema, with legacy headers auto-upgraded on read.

Result

Three counting bugs found and fixed: the sheet-picker was reading the wrong worksheet in the majority of files, and 24 backup snapshots were being counted as live records. Corrected figures changed the operating conclusion — of ~654 uncontacted records, only 41 actually held an email address, which moved the bottleneck from sourcing to enrichment.

Learned

Found by a break in real data, not by reading documentation. It is now a constraint I design under rather than a bug I fixed.

04retrieval corpus · 463k tokens
Broke

A knowledge corpus had grown past any model's context window. Every lookup was a search against a file that could not be loaded at all.

Built

Split synthesis from verbatim archive — 463k tokens down to a 45k loadable master, nothing lost — and added an uncertain-claims register cataloguing every contested or unverified figure, so an agent can check a number before repeating it.

Result

Corpus went from unloadable to loading in a single pass, nothing discarded. 378 in-file anchors and 55 cross-file references repointed, verified to 0 broken links, 0 dead anchors and 0 encoding corruption across 177 files.

Learned

I tested stripping boilerplate first, measured the gain at under 1%, and dropped my own idea. The problem was structure, not filler.

05workspace · pre-commit audit
Broke

A workspace about to receive version control for the first time held ~47 plaintext credentials at its root — including 3 GitHub personal access tokens and an OpenAI key — plus an unignored .env. All of it was in scope for the first commit.

Built

Rewrote the ignore rules and verified every exclusion with git check-ignore before the initial commit rather than after. Also excluded 2.1 GB of model weights and a config file that churns on every launch.

Result

387 files committed with 0 credentials entering version history. No history rewrite was ever needed.

Learned

A secret verified after the commit is not a fix, it is an incident. The check belongs in front of the irreversible step.

06research corpus · source provenance
Broke

Source material was arriving as summaries — reconstructed from memory or lifted from secondary write-ups. They read as plausible and carried claims the original source never made. Nothing downstream could tell them apart from real ones.

Built

A capture rule enforced before anything gets classified or filed: retrieve the full primary transcript first by automated extraction, direct paste second, flagged secondary sources only as a last resort — with source quality declared on every item rather than assumed.

Result

139 sources indexed with provenance recorded per item, and a standing register of every contested or unverified figure in the corpus, so anything reading from it can check a number before repeating it.

Learned

A plausible summary is more dangerous than a missing one. A gap announces itself; a confident reconstruction does not.

07live campaign · silent rate-limiting
Broke

Nine near-identical outreach messages carrying the same link inside a 2.5-hour window tripped a platform spam flag. Nothing was announced — no warning, no error, no notification. The account simply stopped reaching people.

Built

Operating rules derived from the incident and then encoded so they apply without being remembered: per-channel pacing ceilings, mandatory wording variation per recipient, a never-repeat guard that checks send history before composing, and a similarity check that refuses copy too close to anything already sent.

Result

Reachability on the affected batch fell from roughly 80% to 0 — 8 of 8 blocked — which is how the flag was detected at all. Rules were written into a local model so the constraint travels with the work instead of living in my head.

Learned

The platform never told me. A silent policy response looks exactly like bad luck until you watch a rate against its own baseline. Now I instrument the baseline first.
